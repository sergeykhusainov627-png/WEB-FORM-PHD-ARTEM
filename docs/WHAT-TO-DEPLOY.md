## Требования к файлам

* кодировка **UTF-8 без BOM**, переводы строк **CRLF** (оба файла такие; при вставке через
  редактор не давайте ему добавить BOM — иначе Fore не соберётся);

## Ссылки на сборки (обязательно)

* модулю **отчёта** нужна системная сборка `Db` (интерфейс `ILog` для журнала) — уже используется им ранее;
* модулю **формы** для записи в журнал тоже нужна сборка `Db`: в дизайнере у модуля формы добавьте

## Порядок и проверка

1. Залить модуль отчёта (файл 2) и модуль формы (файл 1), сохранить оба объекта.
2. Открыть форму, отметить «Лицензионный участок» (или любые поля), нажать «Применить».
3. Отчёт должен открыться, на листе «Лист1» — таблица с заголовками и данными.
4. Служебная ячейка **`GS1`** на «Лист1» показывает ход выгрузки:
   * `готово: столбцов N, строк M` — всё в порядке;
   * `2. параметры: перенесено N; список полей: массив строк (k), первый: "calyear"` — видно, что ушло в запрос;
   * `ОШИБКА: …` — на каком шаге (1–5) сбой и почему;
   * строки `оформление (ширина/высота): …` — операция не поддерживается веб-клиентом и пропущена,
     это не ошибка (закрепление строк `View.FixedRowsCount` убрано совсем — недоступно в веб-клиенте).

## Журнал (если заведён объект журнала)

Модуль отчёта пишет в журнал `LOG_PHD_TEP_ANALIS_JOURNAL` (namespace `BA_PHD`, класс `KE_CLASS_LOG`)
две записи на каждое открытие: «открытие отчёта» (что перенесено в запрос) и результат
(«выгружено столбцов N, строк M») либо текст ошибки. Поля журнала стандартные, порядок:
`STAMP`, `USER_ID`, `OP`, `OP_SUCC` (1/0), `OBJ_ID`, `OBJ_NAME`, `DESCR`.
Если объекта в репозитории нет — запись молча пропускается (в протокол платформы уходит
сообщение `[АнализТЭП/журнал] запись не удалась`), выгрузка при этом не срывается.

**Что видно в журнале (записи идут по ходу выполнения):** `0/5 запуск`, `1/5 лист`,
`2/5 параметры` (в т.ч. `параметров у запроса/отчёта`, `2/5 итог` и порции `2/5 параметры: ID=значение`),
`3/5 запрос` (+ порции `3/5 колонки`), `4/5 выгрузка` (шапка, строк выгружено), `5/5 оформление`
(границы, шапка, данные, ширина/высота — каждая операция отдельной записью) и `готово`.
Ошибка пишется записью `сбой ...: ОШИБКА: <текст> [модуль: <форма/модуль>, строка: <N>]`,
а сбой отдельного параметра — записью `2/5 параметр <ID>`. Если за прогон в журнале нет
ни одной записи — значит до отчёта дело не дошло (проблема на стороне формы/ссылки).

**Что пишет форма:** `0/3 открытие формы`, `1/3 гиперссылка инициализирована`,
`2/3 значения по умолчанию и список полей установлены`, `3/3 ограничения по СП применены`;
при каждой пересборке — `ссылка сформирована; длина: N симв.`, `полей в списке: N -> …`
и `ссылка: …` порциями по 240 символов; при сбое — `ОШИБКА: <текст> [модуль: <форма>, строка: N]`.
Отбор в журнале: `OP = 'Веб-форма ТЭП'` (форма) или `OP = 'Выгрузка ТЭП (отчёт)'` (отчёт).

## Если что-то из окружения

* заливка шапки использует `GxSolidBrush`/`GxColor` — при ошибке компиляции добавить модулю отчёта
  ссылку на системную сборку `Gx`;
* сопоставление параметров в дизайнере отчёта для списка полей (`ANALYTIC_SET`) больше не нужно —
  модуль передаёт его сам; новые параметры СЭ поедут в запрос автоматически, если так же названы у запроса.
