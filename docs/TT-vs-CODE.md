# ТТ «Анализ и выгрузка данных ТЭП» ↔ код веб-формы: сверка

**Источник ТТ:** `C:\Users\Manya\Downloads\ТТ_Анализ и выгрузка данных ТЭП.xlsx` (5 листов,
дампы — `analiz-tep/tt/*.txt`).
**С чем сверяем:** модуль веб-формы `ANALIZ_TEP_FORM_ON_SHOW` (копия — `analiz-tep/lint/*.fore`),
её зависимости из выгрузки окружения (`full_env_web_form_06102026`, см. `PEFX-EXPORT-FINDINGS.md`).
**Машинная сверка:** `analiz-tep/tools/tt-vs-code2.py` → `analiz-tep/tt/tt-vs-code2.md`
(по идентификаторам полей и по зависимостям формы), `analiz-tep/tools/tt-dump.py` → дампы листов.

> **Важное уточнение терминологии.** «СЭ» в ТТ и в коде — это **Селекционный экран** (экран подбора
> параметров), а не «структурный элемент». Комментарий в коде «Параметры СЭ регламентного отчёта
> с кнопкой» читается как «параметры селекционного экрана для отчёта с кнопкой».

## 2. Верхний уровень СЭ: требование ↔ код

| Требование ТТ | В коде | Статус |
|---|---|---|
| Год, по умолчанию **текущий год**, справочник `DIC_PHD_DATE_APPROVING` | `D_CALYEAR` есть; автоподстановка **закомментирована** (жёстко «2024»); в зависимостях формы вместо ожидаемого справочника — `DICT_PHD_YEAR_F4` «Годы» | ⚠ частично / сверить источник |
| СП, по умолчанию **СП пользователя**, **многократный выбор**, доступ по ролям | `D_PLANT` есть; `getUserSP` (атрибут `BUS_AREA` пользователя) **написан, но не вызывается**; мультивыбор и ролевая логика не реализованы | ⚠ частично |
| Тип данных, по умолчанию **План ID `0000000001`** (`DICT_DATA_TYPE`) | `D_ZTYPEIND` есть; автоподстановка **закомментирована** (`"0000000001"`) | ⚠ частично |
| ТЭП — **не обязательный, многократный** (`RDSD_INDS`) | `D_ZLIB_INDC` есть; обязательность/мультивыбор в коде не выражены | ⚠ уточнить |
| «Условия выборки» — установлен по умолчанию, показывает разделы с полями фильтрации | 18 вкладок `WebTabPage` покрывают разделы | ✅ в основном |
| «Поля для вывода» — разделы и поля для отчёта | реализовано 58 чек-боксами → `P_FIELD_LIST`; часть групп отсутствует (см. §4) | ⚠ частично |
| **«Выводить коды аналитик»** — добавляет в отчёт поля с кодами | чек-бокс `CB_DISPLAY_CODE_ANALYT` объявлен, **обработчика нет** | ❌ нет |
| **«Выводить информацию по статусам»** — добавляет поля статусов | чек-бокс `CB_DISPLAY_INFO_BY_STATUS` объявлен, **обработчика нет** | ❌ нет |
| Роли: `PHD_ADMIN`/`PHD_CURATOR_***` — любое СП; остальные — только своё, изменение запрещено | ролевой логики нет; `getUserSP` не используется | ❌ нет |

## 5. Соответствие по идентификаторам полей отчёта (лист «Вывод полей в отчете»)

Машинная сверка идентификаторов ТТ с именами в коде (параметры гиперссылки + значения `P_FIELD_LIST`)
показала: **48 из 128** пунктов вывода имеют в коде одноимённый идентификатор (остальные — это
периоды/статусы, у которых в ТТ идентификатор задан выражением `ZSIU_INDV при QUARTER=…`, а не именем).

**Идентификаторы ТТ, которых в коде нет вовсе** (и которые нужно добавить, если соответствующие
поля выводятся):
`ZPH_EPOK` (ЭСО покуп), `ACTVTS` (Вид деятельности), `OWNER` (Владелец ТЭП), `ZF_NUMB`
(Формы отчётов, ТЭП-источник), `ID1` (Вид показателя).

**Имена в коде, которых нет в колонках идентификаторов ТТ** (риск: параметр молча отбрасывается
`CObjectParamManager.GetObjectParamValues`, см. `PEFX-EXPORT-FINDINGS.md` §2.2):
`CALYEAR`, `PLANT`, `ZTYPEIND`, `SOLD_TO`, `ZORGUNIT`, `PERIOD_TYPE`, `ZPH_USR2`, `ZPHD_STAT`,
`ZPHD_SPR`, `ZPHD_NOP1`, `ZPHD_PHD`, `ZPHD_PRIZ`.
Из них по смыслу совпадают, но названы иначе: `PERIOD_TYPE` ↔ `PERIOD_TY`, `ZPH_USR2` ↔ `CODE_ZPH_USR0`,
`SOLD_TO` ↔ `KEY`, «Год»/«СП» ↔ `YEAR`/`SP`. **Это надо сверить с фактическими идентификаторами
параметров/полей отчёта `PRX_ANALYSIS_TEP`** — иначе часть выбора просто не доедет до отчёта.
`ZPHD_PHD` и `ZPHD_PRIZ` в ТТ не упоминаются вовсе — уточнить их назначение.

## 7. Сводка: что готово, что нет

**Готово (совпадает с ТТ):**
* 41 поле фильтрации из 57 — комбобоксы с верными справочниками, обработчики пишут параметры в ссылку;
* 58 флажков вывода с рабочими обработчиками (`P_FIELD_LIST`), включая энергоснабжение, геологию,
  кап.строительство, экологию, прочие аналитики;
* механизм «кнопка ОК» (гиперссылка в ячейке A1 отчёта `PRX_ANALYSIS_TEP_BUTTON_OK`) и генерация
  ссылки через `COpenHyperlink` — рабочий и документированный (`PEFX-EXPORT-FINDINGS.md` §2).

**Частично:**
* значения по умолчанию (Год = текущий, Тип данных = План `0000000001`) — закомментированы;
* список полей по умолчанию — `"CALYEAR,PLANT,ZLIB_INDC"` одной строкой вместо набора
  «Год, СП, ТЭП, Ед.измерения + I кв., II кв., 6 мес., III кв., 9 мес., IV кв., Год»;
* раздел «Данные расчёта» — 2 поля из 3.

**Отсутствует:**
* чек-боксы «Выводить коды аналитик» и «Выводить информацию по статусам» (обработчиков нет);
* 19 периодов (месяцы/кварталы) — обработчики пусты;
* группы вывода «С начала года» (19) и «Корректировки» (19) — нет контролов;
* раздел «Данные показателя» (3 комбобокса + чек-бокс) и зависимые выборки (§6);
* 2 текстовых поля и 4 календаря (сейчас 4 из них смоделированы комбобоксами);
* ролевая модель доступа к СП;
* поля-идентификаторы `ZPH_EPOK`, `ACTVTS`, `OWNER`, `ZF_NUMB`, `ID1` и сверка 12 «иных имён».

## 8. Что предлагаю сделать (по этапам)

1. **Сверить идентификаторы** кода (`CALYEAR`, `PLANT`, `ZTYPEIND`, `PERIOD_TYPE`, `ZPH_USR2`,
   `SOLD_TO`, `ZORGUNIT`, `ZPHD_*`) с фактическими параметрами отчёта `PRX_ANALYSIS_TEP` и полями
   `P_FIELD_LIST` — это дешевле всего и снимает риск «молча пустого» результата.
2. **Убрать ручной редактор строки** (`UpdateOpenDefHlink` + 5 вложенных подпрограмм) и оставить
   `Hyperlink.SetParamValueFromSelection` + один `Generate` на обработчик (см. `ANALIZ-TEP-webform.md`,
   практические выводы).
3. **Дозакрыть флажки:** периоды (19), «с начала года» (19), «корректировки» (19), «Данные показателя»,
   «Выводить коды аналитик», «Выводить информацию по статусам» — всё это одна и та же операция
   «добавить/убрать идентификатор в `P_FIELD_LIST`»; удобно сделать общей функцией и навесить на
   чек-боксы, а не писать 60 обработчиков.
4. **Значения по умолчанию** — включить: текущий год, СП пользователя (`getUserSP`), Тип данных «План»,
   и дефолтный набор полей вывода; добавить ролевую логику по СП (`PHD_ADMIN`/`PHD_CURATOR_***`).
5. **Заменить 4 комбобокса-«даты» и добавить 2 текстовых поля** (`WebDateTimePicker` ×4, `WebInput` ×2)
   — сейчас на форме 1 пикер и 1 поле ввода, оба без обработчиков.
6. **Отдельная задача — зависимые выборки** (§6): понадобятся `TBL_IDLNK`, `TBL_ZIDNFORM`,
   `DICT_PHD_GROUPS`, `RDSD_ACTVTS`, `RDSD_OWNERS`; логика описана в ТТ по шагам, включая «в деве
   `0000000362` / в проде `0000000484`» — это лучше вынести в константы/настройку стенда.
