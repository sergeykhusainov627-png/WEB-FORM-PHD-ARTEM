# План по ТЗ от 09.10.2026 (письма «Выгрузка ТЭП 1/2» + ТТ xlsx)

Разбор четырёх пунктов письма и что для каждого нужно сделать: на форме (логика существующих
контролов), в дизайнере формы (создание/привязка контролов — делает заказчик) и в отчёте/запросе.

| № | Пункт ТЗ | Где делается | Состояние |
|---|---|---|---|
| 1.1 | чек-бокс «Поля для вывода» → в отчёте появляется соответствующий столбец | форма + отчёт | **форма готова**: список выбранных аналитик уходит массивом в `P_FIELD_LIST`/`ANALYTIC_SET` (нижний регистр), запрос строит из него SELECT/GROUP BY. **Нужно в отчёте:** сопоставить параметр запроса `ANALYTIC_SET` с параметром отчёта `P_FIELD_LIST` |
| 1.2 | чек-бокса нет → данные по этой аналитике не разрезаются, а суммируются | запрос | выполняется автоматически: невыбранная аналитика не попадает ни в SELECT, ни в GROUP BY. Проверить на стенде после сопоставления параметра |

## Сверка «форма → запрос → отчёт» по параметрам

Сделана скриптом `analiz-tep/tools/check-params.py` (вне репозитория) по выгрузке
`full_env_web_form_06102026 (1).pefx`; протокол — `analiz-tep/out/params-check.txt`.

* форма пишет **48** параметров-фильтров + `P_FIELD_LIST`/`ANALYTIC_SET` (массив) + `CALYEAR`;
* в запросе `QRY_PHD_MULT_DATA_COPY1` — **51** параметр, все используются в SQL;
* параметров, которых нет в запросе, форма не пишет — лишних нет;
* **не хватало трёх** (исправлено): `ZPHD_NCH`, `ZPHD_KON` (обработчики присваивали значение только
  локальной переменной с пометкой «// Нет связи с параметром») и `ZINDTXT1` (обработчик был пуст);
* в отчёте `PRX_ANALYSIS_TEP` не сопоставлены с запросом: `ANALYTIC_SET` (K=6), `ZTYPEIND` (K=52),
  `ZGEN_POD` (K=89).

## Что нужно создать/поправить в дизайнере формы (заказчик)

1. `ANALYTIC_SET` — не контрол: это сопоставление в отчёте (см. ниже).
2. `Input_ZPHD_COMM` — WebInput, подпись «Мероприятие», событие `OnTextChanged` (ТТ: текстовое,
   ручной ввод). После появления контрола подключаю параметр `ZPHD_COMM` (запрос его ждёт).
3. `CB_DISPLAY_CODE_ANALYT` — WebCheckBox, «Выводить коды аналитик», событие `OnChange`.
4. `CB_DISPLAY_INFO_BY_STATUS` — WebCheckBox, «Выводить информацию по статусам», событие `OnChange`.
5. `CB_NOVEMBER`, `CB_THIRD_QUARTER` — WebCheckBox «Ноябрь» и «III кв.» (или переименовать существующие,
   у которых обработчики называются `CbNovemberOnChange`/`CbThirdQuarterOnChange`).
6. Одиннадцать чек-боксов полей вывода — список в `docs/CONTROLS-TO-ADD.md`.

После добавления каждого контрола достаточно пересобрать модуль
(`tools/patch-webform.py` → `tools/cleanup-unused.py`) — строка в таблице полей, вызов
`CollectIfChecked` и тело обработчика появятся автоматически.

## Что нужно сделать в отчёте `PRX_ANALYSIS_TEP`

1. Источник данных `QRY_PHD_MULT_DATA_COPY1` → «Параметры» → сопоставить:
   * `ANALYTIC_SET` ← `P_FIELD_LIST` (ключ к пунктам 1.1/1.2 и к исчезновению невыбранных колонок);
   * `ZTYPEIND` ← `ZTYPEIND`;
   * `ZGEN_POD` ← `ZGEN_POD`.
2. Для пункта 4 — вывести пользовательские наименования (join к справочникам) и, при установленном
   чек-боксе кодов, дополнительный столбец с кодом.
3. Для пункта 2 — свернуть варианты/типы данных в столбцы (правка запроса).

Пункты 2 и 4 — это правки запроса/отчёта; текст SQL подготовлю отдельно (запрос уже динамический
по аналитикам, схема свёртки периодов в нём есть — по ней и делаем).

## Что уже проверено и работает со стороны формы

* список полей — строго по отмеченным чек-боксам, массивом в нижнем регистре, без периодов
  `ZSIU_INDV_*` (их в запросе нет);
* `CALYEAR` уходит всегда («Год» — поле вывода по умолчанию, контрола для него нет);
* генерация гиперссылки и запись параметров не роняют форму при ошибке (текст ошибки — в `TextArea1`);
* ссылки только на подтверждённые контролы (иначе дизайнер формы падает с «Ошибка сервера»).
