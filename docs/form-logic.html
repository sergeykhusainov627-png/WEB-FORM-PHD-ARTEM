Шапка формы
Фильтры-справочники: Год D_CALYEAR, СП D_PLANT, ТЭП D_ZLIB_INDC, Тип данных D_ZTYPEIND

Поля для вывода — 95 чек-боксов CB_* по разделам (Основные данные, Значения ТЭП, Энергоснабжение, Геология и бурение, Кап.строительство, Экология, Прочие аналитики, Данные показателя, Данные расчета)

выбрал значение в комбо → мгновенно меняется ссылка на отчёт

нажал «Применить» → открывается отчёт по сформированной ссылке

1) addFieldsWithoutCheckBox → «Год» (CALYEAR) всегда: чек-бокса для него нет
2) CollectIfChecked(CB_X, "CB_X") × 75 → fieldIdByControl → таблица _fieldIds (88 строк) → addFieldToList // отмечен — попал в список, снят — нет
3) режим кодов: P_ANALYTIC_SET ← список полей-кодов выбранных аналитик
4) режим статусов: к выбранным периодам добавляются поля <период>_STAT
5) analyticSetArray → МАССИВ идентификаторов в нижнем регистре [calyear, plant, zlib_inc, …] // без периодов ZSIU_INDV_*
6) SetParamSafe("P_FIELD_LIST", массив) и SetParamSafe("ANALYTIC_SET", массив)
7) SafeGenerate → ссылка перегенерирована из менеджера параметров
5Сервисный слой (защита и диагностика)

_lastError → TextArea1 — текст ошибки виден прямо на форме

3. Отчёт и данные
Гиперссылка (её и открывает «Применить»)
@PRX_ANALYSIS_TEP(PLANT=…;CALYEAR=…;ZLIB_INFS=…; P_FIELD_LIST=[calyear,plant,zlib_inc,act_unit])
Отчёт PRX_ANALYSIS_TEP
источник данных — запрос QRY_PHD_MULT_DATA_COPY1
параметры отчёта → параметры запроса (сопоставление в дизайнере отчёта; в отчёте ещё не сопоставлены ANALYTIC_SET, ZTYPEIND, ZGEN_POD)
Запрос: из чего получаются столбцы
SELECT :ANALYTIC_SET, «Январь» … «Год» FROM VIEW_PHD_MULT_LEFT WHERE (ZPHD_STAT IN (:ZPHD_STAT) OR COALESCE(:ZPHD_STAT,'')='') AND … GROUP BY :ANALYTIC_SET, zlib_indc, calyear, plant
✔ аналитика в списке → отдельный столбец со своими значениями
✔ аналитики нет в списке → по ней не режем: значения суммируются
:PARAM — фильтры из «Условий выборки»; пустой параметр = условие не применяется
Результат для пользователя
отмечен чек-бокс → появился столбец; снял → столбца нет, данные сложились
имена столбцов и коды — задача отчёта (пункты 2 и 4 ТЗ)
Правила и тонкости, которые видны из схемы
  • Почему ссылки только на «подтверждённые» контролы. Если модуль ссылается на компонент, которого нет на форме, дизайнер формы падает с «Ошибка сервера». Поэтому контролы без обработчиков в исходном модуле (20 штук) сейчас не собираются: у них нет строки в таблице _fieldIds, строки CollectIfChecked и обработчика. После подтверждения по экранам их включаем (по 3 строки на контрол).
  • Один сборщик на всю форму. Отдельного «сборщика имён» на каждый чек-бокс не нужно: RefreshFieldList пересобирает список целиком, проходя все контролы; обработчик чек-бокса — только триггер пересборки.
  • Почему «Год» уходит всегда. В ТЗ это поле вывода «по умолчанию», но чек-бокса для него на форме нет — поэтому он добавляется в список безусловно (addFieldsWithoutCheckBox).
  • Почему периоды не уходят в список полей. Идентификаторов ZSIU_INDV_* в запросе нет (месяцы и кварталы в нём — фиксированные столбцы), поэтому в ANALYTIC_SET они не попадают — иначе SQL сломался бы.
  • До отчёта доходит только объявленное. Платформа молча отбрасывает параметры, которых нет у объекта: поэтому P_FIELD_LIST работает лишь после сопоставления с ANALYTIC_SET в отчёте.
  • Не реализовано: обработчики кнопок «Применить»/«Отменить» (ButtonApply, ButtonCancel) — сейчас они ничего не делают; открытие отчёта идёт по гиперссылке.
