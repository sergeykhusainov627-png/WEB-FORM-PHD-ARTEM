# Изменения в модуле веб-формы от 06.10.2026 (по ТТ «Анализ и выгрузка данных ТЭП»)

**Файл:** `Fore/WFRM_PHD_ANALISIS_TEP_COPY_FOR_DEV.fore` (1917 строк; было 1574).
**Эталон со стенда:** `Fore/_stand/WFRM_PHD_ANALISIS_TEP_COPY_FOR_DEV.stand.fore` (байт-в-байт со стенда).
**Скрипт правки:** `tools/patch-webform.py` (применяется к эталону, повторяемый), проверка —
`tools/check-webform.py`. Протоколы — `docs/checks/`.

> **Правка не создаёт и не переименовывает компоненты формы.** Состав объявлений контролов идентичен
> оригиналу: 238 объявлений, из них 181 компонент `Web*` (95 `WebCheckBox`, 58 `WebDimensionCombo`,
> 18 `WebTabPage`, 3 `WebTabControl`, 2 `WebButton`, по одному `WebTextArea`/`WebPanel`/`WebReportBox`/
> `WebInput`/`WebDateTimePicker`). Добавлены только два **невизуальных** поля-таблицы
> `_fieldIds`/`_codeIds: IHashtable`, константы и методы. Проверяется автоматически:
> `python tools/check-webform.py <модуль> <эталон>` — появление компонента или потеря объявления
> относительно эталона считается ошибкой.

## 1. Что сделано

### 1.1 «Поля для вывода» — список полей формируется целиком

| Было | Стало |
|---|---|
| 58 обработчиков добавляли/убирали по одному идентификатору в `P_FIELD_LIST`; 19 периодов (месяцы/кварталы) имели **пустые** обработчики; 18 чек-боксов **без обработчиков** | Единая таблица `InitOutputFieldIds` (**88 идентификаторов**) + `RefreshFieldList`: список каждый раз пересобирается по фактическим состояниям чек-боксов формы |
| Список полей по умолчанию — одна строка `"CALYEAR,PLANT,ZLIB_INDC"` | **Вывод строго по чек-боксам:** поле попадает в `P_FIELD_LIST` только если его чек-бокс отмечен; снял флажок — поле в отчёте не выводится. Единственное исключение — «Год» (`CALYEAR`): чек-бокса `CB_CALYEAR` в форме нет, поле выводится всегда (одна строка в `addFieldsWithoutCheckBox`; если чек-бокс появится — убрать её и завести поле в таблице) |
| Чек-боксы по умолчанию не отмечены | Отмечаются программно (ТТ, «установлен по умолчанию»): СП (`CB_PLANT`), ТЭП (`CB_ZLIB_INDC`), Ед.измерения (`CB_ACT_UNIT`), I кв., II кв., 6 мес., III кв., 9 мес., IV кв., Год — любой из них пользователь может снять |

Поля, заведённые заново (идентификаторы из ТТ): «Вид деятельности» `ACTVTS`, «Вид показателя» `ID1`,
«Формы отчётов» `ZF_NUMB`, «Владелец ТЭП» `OWNER`; 19 периодов `ZSIU_INDV_01…12`, `_Q0…_Q6`.

### 1.2 Режимы вывода

* **«Выводить коды аналитик»** (`CB_DISPLAY_CODE_ANALYT`) — в параметр `P_ANALYTIC_SET` пишется список
  полей-кодов выбранных аналитик (ТТ, колонка «Поле» при «Выводить код = да»): `SP`, `KEY`,
  `CODE_ZPH_USR0`, `PERIOD_TY`.
* **«Выводить информацию по статусам»** (`CB_DISPLAY_INFO_BY_STATUS`) — к каждому выбранному периоду
  добавляется поле статуса `<период>_STAT` (`C_STATUS_FIELD_SUFFIX`).

### 1.3 Значения по умолчанию и ограничение по СП

* Год — **текущий** (`DateTime.Now.Year`, атрибут `NAME`).
* СП — из **основной записи пользователя** (`BUS_AREA`), тип данных — «План» (`0000000001`, атрибут `ID`).
* **Ограничение на вывод СП** (ТТ): `PHD_ADMIN` и `PHD_CURATOR_*` выбирают любое СП; остальным
  подставляется СП пользователя и поле блокируется (`D_PLANT.Enabled := False`).

### 1.4 Механизм гиперссылки приведён к фактическому поведению

* `UpdateOpenDefHlinkFromSelection` теперь пишет значение прямо в менеджер параметров
  (`Hyperlink.SetParamValueFromSelection`) — тот же путь, которым пользуются все обработчики.
* **Удалён ручной разбор строки действия** (`UpdateOpenDefHlink` + 5 вложенных подпрограмм, ~120 строк):
  по исходнику `COpenHyperlink.Generate` всё равно пересобирает строку из менеджера параметров
  (`docs/PEFX-EXPORT-FINDINGS.md` §2.1), а сам разбор мог падать на `String.SubString(-1)`.
* 4 прямых обращения `_AnalyzTepHyperlink.SetParamValue(...)` (`ZLIB_INFS`, `ZBUR_BEG`, `ZBUR_END`,
  `ZPKR_SUBP`) заменены на свойство `Hyperlink` + `Generate` — раньше эти параметры попадали в ссылку
  «когда-нибудь потом».
* Отладочная строка `TextArea1.Lines.Add(Hyperlink.tst)`, на которой держалось создание `COpenHyperlink`,
  заменена явным `_AnalyzTepHyperlink := Hyperlink;` в `onShow`.
* `getUserSP` больше не падает при отсутствии атрибута `BUS_AREA` (Try/Except + проверки `Null`).
* Добавлены обработчики-дубли `CB_NOVEMBEROnChange` / `CB_THIRD_QUARTEROnChange` — прежние
  `CbNovemberOnChange` / `CbThirdQuarterOnChange` сохранены (в дизайнере может быть привязан любой).

**Осталось по желанию (на работу не влияет):** в 48 обработчиках справочников один и тот же параметр
пишется дважды — через `UpdateOpenDefHlinkFromSelection` и следом напрямую через
`Hyperlink.SetParamValueFromSelection`. Повторная запись просто перезаписывает значение в хеш-таблице,
так что это безвредно; при желании вторую строку из обработчиков можно убрать.

### 1.5 Ограничения платформы, учтённые в коде

* **`IWebComponents` нельзя объявлять как тип** (в отличие от `IWebComponent`), поэтому перебор
  компонентов формы (`Self.Components`) в модуле **не используется**: состояния чек-боксов собираются
  явным списком вызовов `CollectIfChecked(CB_X, "CB_X")` внутри `RefreshFieldList`. Список
  генерируется скриптом `tools/patch-webform.py` из таблицы `InitOutputFieldIds` (88 строк),
  а `tools/check-webform.py` отдельно проверяет, что `IWebComponents` и `Self.Components`
  в живом коде не встречаются вовсе.
* Идентификаторы полей берутся из таблицы по имени контрола (`fieldIdByControl`), а поля статусов
  и коды аналитик выводятся из уже собранного списка `fieldList` — без обращения к коллекции компонентов.
* Пустое значение параметра в менеджер не пишется: `CObjectParamManager.GetObjectParamValues`
  присваивает значения как есть и на `Null` упал бы, поэтому ненужный параметр **удаляется**
  из хеш-таблицы (`setParamOrRemove`).

## 2. Что обязательно проверить на стенде

| # | Что | Почему |
|---|---|---|
| 1 | Идентификаторы, помеченные в коде «уточнить»: `ZPH_HIGHER` (Вышестоящий ТЭП), `ZPH_FUNC` (Функция/задача), `ZPH_VOLUME` (Объёмный), `ZPH_TRUD` (Трудоёмкость), `ZPH_PRICE_CP` (В сопоставимых ценах), `ZPH_PRICE_CD` (В действующих ценах), `ZPH_ACTTYPE2` (Вид работ (классификация)) | в ТТ идентификатор не указан — принят по имени поля |
| 2 | Имена полей периодов `ZSIU_INDV_01…12`, `_Q0…_Q6` | в ТТ период задан выражением `ZSIU_INDV при QUARTER/CALMONTH`, а не именем поля |
| 3 | Параметр `P_ANALYTIC_SET` и суффикс `_STAT` | принято по смыслу ТТ («добавляются поля с кодами»/«со статусами»); уточнить у владельца отчёта |
| 4 | Привязки событий `onChange` у новых обработчиков («Данные показателя», периоды) | события навешиваются в дизайнере формы |
| 5 | Роли `PHD_ADMIN` / `PHD_CURATOR_*` | проверить на реальном пользователе: поле СП должно быть заблокировано у обычного пользователя |
| 6 | Отчёт `PRX_ANALYSIS_TEP`: наличие и параметры (`P_FIELD_LIST`, `P_ANALYTIC_SET`) | неизвестные параметры отбрасываются молча |

**Что в этой правке НЕ реализовано** (в ТТ такие поля есть, но **новые компоненты не создавались** —
правка ограничена логикой по существующим контролам; перечисленное требует отдельного решения):

* группа «Значения ТЭП с начала года» — 19 полей (`TBL_PHD_FAP_MULT.ZVALUE_SNG`);
* группа «Значения корректировок ТЭП» — 19 полей (`ZSIU_INDV` + `ZLIB_INFS=KOROUND`);
* поле «Класс вида оборудования» (`ZCLSVOBOR`) — есть в ТТ, контрола на форме нет;
* 5 чек-боксов, назначение которых в ТТ не найдено: `CB_ANALYTIC_SET`, `CB_AREA`,
  `CB_ESTIMATED_PRICES`, `CB_MVP_TEP`, `CbESO3` — оставлены без идентификаторов;
* обработчики кнопок `ButtonCancel` / `ButtonApply` (в правку не входили).
