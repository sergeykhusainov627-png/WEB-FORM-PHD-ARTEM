# Почему выводятся невыбранные колонки и что с этим делать

Разобрано по выгрузке `full_env_web_form_06102026 (1).pefx` (в ней появились запрос
`QRY_PHD_MULT_DATA_COPY1` и отчёт `PRX_ANALYSIS_TEP`).

## Как устроен вывод

Отчёт `PRX_ANALYSIS_TEP` («Отчет анализ и выгрузка данных ТЭП») берёт данные из запроса
`QRY_PHD_MULT_DATA_COPY1`. В запросе есть параметр **`ANALYTIC_SET`** — **массив** идентификаторов
аналитик в нижнем регистре (значение по умолчанию — 77 штук: `zphd_pern`, `sold_to`, `vendor`,
`zhrgrpmo`, `calyear`, `plant`, `zlib_infs`, …, `zclsvobor`, `zlib_indc`, `act_unit`, `zphd_stat`).

В тексте запроса этот параметр подставлен **прямо в список выборки**:

```sql
WITH TMP_TBL AS (
    SELECT
        :ANALYTIC_SET,                       -- <- сюда подставляются выбранные аналитики
        (SELECT ACTVTS FROM t1895280 ...) AS "Код вида деятельности",
        ...
    FROM VIEW_PHD_MULT_LEFT
    ...
    GROUP BY :ANALYTIC_SET, zlib_indc, CALYEAR, PLANT
)
...
SELECT
    :ANALYTIC_SET,
    "Код вида деятельности", "Наименование вида деятельности", "Формы ТЭП СНГ",
    "Январь" … "Декабрь", "I кв." … "IV кв.", "Год",
    "Январь. С нач.года" … "Год. С нач.года"
FROM Main_Data;
```

То есть **динамический список колонок в запросе уже реализован** — ровно так, как и требовалось:
какие идентификаторы пришли в `ANALYTIC_SET`, такие колонки и попадут в результат.

## Где обрыв

В отчёте `PRX_ANALYSIS_TEP` объявлен параметр **`P_FIELD_LIST`** («Список полей», тип — массив),
но он **ни с чем не сопоставлен**. В сопоставлении параметров источника данных участвуют 48
параметров запроса из 51; не сопоставлены три:

| Параметр запроса | Что это | Последствие |
|---|---|---|
| `ANALYTIC_SET` (K=6) | набор выводимых аналитик | отчёт всегда получает значение по умолчанию — все 77 → все колонки, невыбранные пустые |
| `ZTYPEIND` (K=52) | «Вид данных» (комбо `D_ZTYPEIND` на СЭ) | фильтр с экрана до запроса не доходит |
| `ZGEN_POD` (K=89) | «Участок недр» | фильтр с экрана до запроса не доходит |

## Что сделать в отчёте (одно действие)

Открыть `PRX_ANALYSIS_TEP` → источник данных `QRY_PHD_MULT_DATA_COPY1` → страница «Параметры» →
сопоставить параметр запроса **`ANALYTIC_SET`** с параметром отчёта **`P_FIELD_LIST`**.
Заодно сопоставить `ZTYPEIND` и `ZGEN_POD` (иначе соответствующие фильтры СЭ не работают).

После этого набор колонок в отчёте будет определяться тем, что отмечено на СЭ.

## Что отправляет форма (уже реализовано)

| Параметр | Значение |
|---|---|
| `P_FIELD_LIST` | **массив** идентификаторов в нижнем регистре, например `[calyear,plant,zlib_indc,act_unit]` |
| `ANALYTIC_SET` | то же значение (страховка: в черновике автора формы — строка 393 эталона — в ссылку писался именно `ANALYTIC_SET`). Лишний параметр платформа отбрасывает молча |

Массивы в ссылке платформа сериализует как `[a,b,c]` — это проверено по её же коду
(`CNavigationLinkBuilder.ComposeParamTransferValue`: `result := String.Format("[{0}]", result)`).

Идентификаторы периодов (`ZSIU_INDV_01…12`, `ZSIU_INDV_Q0…Q9` — 17 чек-боксов) в список **не входят**:
в запросе таких аналитик нет, подстановка сломала бы SQL.

## Что остаётся за пределами этой правки

1. **Периоды.** Запрос всегда выводит 19 фиксированных колонок («Код/Наименование вида деятельности»,
   «Формы ТЭП СНГ», 12 месяцев, I–IV кв., «Год»). Чек-боксы периодов на СЭ сейчас ни на что не влияют.
   Чтобы периоды управлялись с экрана, нужен второй массивный параметр запроса, например `:PERIOD_SET`,
   подставленный в тот же SELECT — тогда форма будет передавать выбранные подписи (`"Январь"`, `"I кв."`, …).
2. **«Значения ТЭП с начала года».** В запросе эти колонки считаются (`ZVALUE_SNG`, 38 штук), но в списке
   полей отчёта (96 штук) их нет — отчёт отстал от запроса, нужно обновить состав полей источника данных.
3. **«Формы ТЭП СНГ»** — колонка есть в запросе, в отчёте её нет (та же причина).
4. Если после сопоставления `ANALYTIC_SET` колонки всё равно останутся пустыми — значит шаблон листа
   статичен и колонки нужно скрывать кодом отчёта (`TabSheet.Column(i).Hidden := True`, свойство
   `ITabRange.Hidden` есть в API). Тогда нужен доступ к модулю отчёта.

## Как проверить

1. На СЭ снять **все** флажки «Поля для вывода», оставить только «СП» и «Единица измерения», нажать «Ок».
2. Если после сопоставления параметра колонок стало мало (только выбранные + фиксированные) — механизм
   работает, дальше просто дорабатывать список полей.
3. Если колонок всё ещё 96 — см. пункт 4 выше.
