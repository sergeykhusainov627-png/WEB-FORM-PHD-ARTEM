# Скрытие невыбранных колонок — что должен сделать отчёт

## Коротко

Форма свою часть уже делает: передаёт отчёту список выбранных полей. **Видимостью колонок управляет
сам отчёт `PRX_ANALYSIS_TEP`** — сейчас он выводит фиксированный широкий набор колонок, поэтому
невыбранные поля видны пустыми. Чтобы они исчезали, правку нужно внести в отчёт.

## Контракт «форма → отчёт»

| Что | Значение |
|---|---|
| Параметр | `P_FIELD_LIST` (имя взято из исходного модуля формы, строка 1560 эталона) |
| Формат | идентификаторы полей через запятую с пробелом: `PLANT, ZLIB_INDC, ZSIU_INDV_Q1` |
| Когда отправляется | при каждом изменении любого чек-бокса «Поля для вывода» **и при открытии формы** |
| Что ещё уходит отчёту | параметры условий выборки (`CALYEAR`, `PLANT`, `ZTYPEIND`, `ZLIB_INFS`, `ZBUR_BEG`, …), список кодов аналитик `P_ANALYTIC_SET` (режим «Выводить коды аналитик») |

Требование ТТ (лист «Вывод полей в отчете», колонка «Условие вывода»): каждое поле выводится
«**если установлен в разделе "Поля для вывода"**». То есть отчёт обязан отфильтровать колонки по
`P_FIELD_LIST`, а при установленном чек-боксе «Выводить коды аналитик» — дополнительно вывести поля
с кодами из колонки «Поле» (лист «Вывод полей в отчете»).

## Что нужно сделать в отчёте

**Вариант A — отчёт регулярный (Excel-шаблон со статичными колонками).** Добавить в модуль отчёта
обработчик открытия/подготовки, который:

1. читает параметр `P_FIELD_LIST` и разбирает его по `", "` в список идентификаторов;
2. для каждой колонки шаблона по карте «идентификатор поля → индекс колонки» проверяет, есть ли
   идентификатор в списке, и скрывает колонку, если нет (колонка не должна занимать место и не должна
   попадать в выгрузку);
3. если по колонке выводится несколько полей (например, «Наименование ТЭП» при установленном ТЭП) —
   скрывать/показывать их согласованно по тому же правилу.

**Вариант B — отчёт процедурный (лист строится кодом).** Строить лист только по выбранным
идентификаторам: порядок колонок — как в ТТ, «Год»/«СП»/«ТЭП»/«Ед.измерения» первыми.

В обоих случаях: если `P_FIELD_LIST` не передан или пуст — разумно вывести поля «по умолчанию»
(Год, СП, ТЭП, Ед.измерения), а не все подряд.

## Открытые вопросы к владельцу отчёта

1. **«Год»**: в ТТ поле отчёта называется `YEAR` (лист «Вывод полей в отчете», `TBL_PHD_FAP_MULT.YEAR`),
   а в исходном модуле формы в список по умолчанию попадал `CALYEAR`. Какой идентификатор ждёт отчёт
   в `P_FIELD_LIST`?
2. **Суффикс `_STAT`**: в ТТ описано «при установке чек-бокса к выбранным полям добавляются поля
   с кодами значений и справочника» — уточнить точный вид имён полей статусов.
3. **Порядок колонок** в отчёте — фиксированный по ТТ или по порядку в `P_FIELD_LIST`?
4. Пустой `P_FIELD_LIST` — что показывать (по ТТ логично только Год, СП, ТЭП, Ед.измерения).

## Как проверить, видит ли отчёт параметр

На форме отметить **только «СП»** (снять остальные флажки), нажать «Ок». Если колонки в отчёте
не изменились вообще — параметр не читается (нужна правка отчёта по варианту A или B). Если изменились
частично — можно точечно доработать те колонки, которые не реагируют.
